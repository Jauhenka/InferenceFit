# E0.5 Real-World Validation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Validate InferenceFit E0 end to end with a public-safe structured-extraction workload, fixture candidates, and opt-in Fireworks and DeepSeek runs, fixing only demonstrated integration defects.

**Architecture:** Keep the existing EvaluationSpec, OpenAI-compatible adapter, validator, execution, optimizer, and artifact boundaries. Add only a DeepSeek endpoint/credential preset, production-inspired synthetic example assets, and evidence-backed documentation. Run a four-case live probe before the full English sample and preserve each run for artifact and secret checks.

**Tech Stack:** Python 3.11+, Pydantic, httpx, Typer, pytest, Ruff, Hatchling, YAML, JSONL.

**Spec:** User-supplied E0.5 real-world validation brief attached to this task.

## Global Constraints

- Do not copy private or identifying production data; all committed workload content must be invented.
- The unavailable `extract_lead_semantic_units_testcases*` and `merge_new_offers` files must not be claimed as inspected.
- English is primary, with 20–40 distinct cases; multilingual coverage is optional and small.
- Use JSON Schema only as the runtime routing gate; exact expected-value checks remain evaluation-only.
- Reuse the OpenAI-compatible adapter; do not add a vendor SDK or redesign provider abstractions.
- Live calls are opt-in, start with 3–5 cases, use environment credentials, and never persist secrets.
- Do not publish a package or add Cloud, SaaS, database, UI, or semantic-validator scope.

## Review Focus

- A DeepSeek candidate with only `DEEPSEEK_API_KEY` must resolve without requiring a project-specific alias.
- Fenced or malformed model output must become validator failure data, not an engine crash.
- Missing usage values must keep cost unknown while preserving a successful provider observation.
- Fixture examples must demonstrate schema-gated fallback without representing fixture output as live model evidence.
- Live artifacts must omit credential references and secret values while retaining exact provider/model provenance.
