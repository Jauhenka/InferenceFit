# InferenceFit 0.1.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a safe, reproducible, installable, and documented InferenceFit 0.1.0 release candidate without publishing it or pushing a release tag.

**Architecture:** Keep the product code unchanged and add a narrow release-engineering layer around it: single-source package metadata, distribution audit and installed-package smoke scripts, public release documentation, offline CI, and separate Trusted Publishing workflows. Every automated release path builds once, verifies the exact artifacts, and passes those immutable artifacts to publishing jobs.

**Tech Stack:** Python 3.11–3.13, Hatchling, PyPA Build, Twine, pytest, Ruff, GitHub Actions, PyPI Trusted Publishing/OIDC.

**Spec:** `docs/superpowers/specs/2026-09-21-release-0.1.0-design.md`

## Global Constraints

- Preserve distribution name `inferencefit` and version `0.1.0`.
- Support `pip install inferencefit`, `inferencefit --help`, and `from inferencefit import benchmark` from an installed wheel.
- Use only deterministic fixture workloads in ordinary CI and installed-package smoke tests.
- Never require provider credentials or make paid inference calls in ordinary CI.
- Use PyPI Trusted Publishing through OIDC; never add a long-lived upload token.
- Keep TestPyPI and production PyPI workflows and GitHub environments separate.
- Do not publish to production PyPI, create or push `v0.1.0`, force-push, or rewrite history.
- Preserve existing user changes in `README.md`, `LICENSE`, `AGENTS.md`, and `.github/copilot-instructions.md`; stage files explicitly so unrelated files are never swept into a task commit.
- Do not add providers, routing behavior, hosted services, or any other E1 feature.
- Treat missing or failed tests, archive checks, installed-package checks, privacy checks, or name-availability checks as release blockers.
- Account-side Trusted Publisher configuration is a documented human gate, not a reason to add token-based publishing.

## Review Focus

- Source-tree leakage: an installed-distribution smoke run must reject an `inferencefit` import resolved under the repository source root; Task 2 tests this guard.
- Cross-platform entry points: the verifier must locate the temporary environment's interpreter and `inferencefit` executable correctly on Windows and POSIX; Task 2 tests both layouts.
- Archive leakage: `.env`, `.inferencefit`, caches, agent instructions, and internal Superpowers plans must fail distribution audit; Task 3 tests representative forbidden members.
- Immutable publishing: publish jobs must download verified artifacts and contain no build command; Task 6 tests both release workflows structurally.
- Tag/version mismatch: production workflow verification must compare `vX.Y.Z` with built distribution version `X.Y.Z` before publication; Tasks 3 and 6 test and wire this check.
