# Agent UX and Workload Presets 0.2.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship InferenceFit 0.2.1 with three workload presets, safe project initialization, and a portable Agent Skill over the existing benchmark workflow.

**Architecture:** Keep a fixed typed registry separate from static package templates, copy templates into ordinary schema-0.1 projects, and validate generated files through the existing spec and dataset loaders. Package a concise vendor-neutral Agent Skill under `src/inferencefit`, expose only its path through the CLI, and extend the existing archive/install release checks rather than adding a new execution or plugin system.

**Tech Stack:** Python 3.11+, Typer, Pydantic v2, PyYAML, pytest, pytest-asyncio, Hatch/build, Twine, Ruff, static Markdown/YAML/JSONL package resources.

**Spec:** `docs/superpowers/specs/2026-09-30-agent-ux-0.2.1-design.md`

## Global Constraints

- Release version is `0.2.1`; serialized `schema_version` remains `0.1`.
- The built-in preset identifiers are exactly `coding`, `document-processing`, and `structured-extraction` in that order.
- Presets define workload structure and must not contain live model IDs, provider rankings, or hard-coded best-model recommendations.
- Generated projects use the existing `EvaluationSpec`, JSONL `TestCase`, validator, fixture-provider, `benchmark()`, and artifact paths; no second benchmark path is allowed.
- A destination that has any existing filesystem entry is never overwritten; 0.2.1 has no `--force` mode.
- Generated examples and the Agent Skill must say that representative production cases are required before model-selection decisions.
- `inferencefit presets`, `inferencefit init`, and `inferencefit skill path` are non-interactive and have stable concise output and exit behavior.
- The canonical skill follows the Agent Skills `SKILL.md` convention with `name` and `description` frontmatter and one-level references.
- No credential value may be printed, serialized, committed, placed in a generated project, or included in a distribution.
- No new provider, semantic-judge engine, model catalog, dataset downloader, installer framework, plugin system, TUI, GUI, or runtime dependency is added.
- Preserve all 0.2.0 providers, execution, validators, artifacts, resume, CLI, HTTP API, packaging, and historical release documents.

## Review Focus

- A dangling symlink at the destination can report `Path.exists() == False`; Task 2 tests it as an existing conflict and requires `os.path.lexists()`-equivalent behavior.
- A copy or post-copy contract-validation failure can leave a misleading partial project; Task 2 injects each failure and asserts invocation-owned output is removed.
- A fixture sample can be mistaken for benchmark evidence; Task 4 asserts every generated README contains the production-example warning and identifies the fixture as plumbing only.
- Package-data files can pass source tests but disappear from a wheel or sdist; Task 6 requires exact archive members and exercises preset initialization plus skill discovery from both installed artifacts.
- Broad document tasks do not share one metric; Task 4 checks that the document preset labels its sample as classification-shaped and explicitly distinguishes QA, summarization, synthesis, and long-input validation choices.
