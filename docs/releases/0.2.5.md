# InferenceFit 0.2.5 — workspace selection and auditable responses

InferenceFit 0.2.5 is an additive patch over the native Anthropic (Claude) adapter. It retains
serialized `schema_version: "0.1"`, the existing request text and token totals, cost calculation,
latency, retries, CLI, daemon, and benchmark behavior.

For a multi-workspace Anthropic API key, set `ANTHROPIC_WORKSPACE_ID` alongside
`ANTHROPIC_API_KEY`. Native `provider: anthropic` and alias `provider: claude` requests then send
`anthropic-workspace-id`. When the variable is absent or empty, the header is omitted and
single-workspace keys continue to work. Neither value is embedded in source or persisted as a
request header.

Each successful `observations.jsonl` record can now carry optional `raw_response`,
`finish_reason`, `provider_finish_reason`, `provider_request_id`, `reasoning_tokens`,
`reasoning_content`, and `usage_details`. The raw response is provider JSON with credential-bearing
fields and echoed resolved API keys redacted; request and authorization headers are never copied.
Anthropic content blocks, native stop reason, `request-id`, and usage including cache fields are
preserved. Only returned `thinking` blocks become `reasoning_content`. Anthropic does not separately
report reasoning tokens in the Messages usage used here, so `reasoning_tokens` is `null` even when
thinking text is returned. `usage.output_tokens` remains the provider's total output count, not a
calculated final-answer count.

OpenAI Responses also retains returned reasoning token counts and exposed reasoning text or
summaries. Gemini, DeepSeek, and Fireworks use the existing OpenAI-compatible adapter: it retains
their native JSON and usage, and extracts a finish reason, request ID, reasoning count, or
`reasoning_content` only if those fields are actually returned in the compatible response. Unknown
finish reasons remain verbatim in `provider_finish_reason` with normalized `finish_reason: null`.
No hidden chain-of-thought is inferred from answer text. Other vendor-specific fields remain in
`raw_response`; support for every provider-specific metadata shape is not claimed.

Old schema 0.1 observations without these fields reload with `null` defaults. The aggregate
`result.json` format remains unchanged; per-request audit data is in `observations.jsonl`.
No billable provider calls are part of the ordinary tests. Publication, TestPyPI rehearsal, and
release tagging remain human-controlled.
