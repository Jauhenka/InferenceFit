# InferenceFit 0.2.2

InferenceFit 0.2.2 is a generic-provider release. It makes any documented OpenAI-compatible
chat-completions endpoint a first-class, tested candidate through the existing local-first
benchmark core, the shared `OpenAICompatibleProvider`, and the same public `benchmark()` runner.

```bash
pip install inferencefit==0.2.2
```

## `provider: custom`

The canonical public identifier for a supplied endpoint is `provider: custom`. It uses the existing
`CandidateSpec` contract with no new fields:

```yaml
schema_version: "0.1"
dataset:
  path: cases.jsonl
candidates:
  - id: my-provider-model
    provider: custom
    model: some/model-name
    base_url: https://api.example.com/v1
    credential_ref: example-main
```

`provider: custom` requires `base_url`, which must be an absolute `http` or `https` URL with a
hostname. The value is an API base: the shared adapter strips a trailing `/` and appends
`/chat/completions` exactly once. `/v1` is common but not mandatory. Reject blank, whitespace, or
control characters, credentials in URL userinfo, query or fragment, malformed ports, and a full
`/chat/completions` request URL. HTTPS is recommended for remote services; HTTP is allowed for local
and private endpoints in local OSS execution. Never place a secret in any URL component, because the
base URL is persisted in run artifacts.

## Remote Bearer and credentialless localhost

`credential_ref` is the only generic secret input. The environment supplies the referenced value,
for example `INFERENCEFIT_CREDENTIAL_EXAMPLE_MAIN`; inference does not discover provider-specific
variable names. A missing explicit reference fails before the run, while an omitted reference means
credentialless operation. A remote endpoint uses a Bearer `Authorization` header built from the
resolved value exactly as the built-in adapters do.

For a credentialless local endpoint, omit `credential_ref` and use an explicit URL such as
`http://127.0.0.1:8000/v1` or `http://[::1]:8000/v1`; the request then carries no `Authorization`
header. The opaque `credential_ref` persistence contract is unchanged: only the resolved secret
value must be absent from specifications, manifests, observations, results, logs, errors, and other
artifacts. Because user-authored parameter values and the base URL are persisted, secrets must not
be placed there.

## Compatibility and deprecation

Keep existing named providers and URL presets: Fixtures, DeepSeek, Fireworks, Gemini, OpenAI,
OpenRouter, Ollama, and vLLM. A named provider with an explicit `base_url` keeps its 0.2.x
precedence and uses the shared chat path, including `openai` and `openrouter`; this bypasses
provider-specific behavior such as OpenRouter's cost and backend metadata and OpenAI's Responses
API. It is a **backward compatibility** affordance, not the recommended syntax for a new endpoint.

New configurations use `provider: custom`. An unknown provider name **with** `base_url` remains
accepted for 0.2.x compatibility but is **deprecated**: `create_provider()` emits a visible,
secret-safe `UserWarning` directing users to `custom` without repeating user-controlled labels or
URL text, so a misspelled name no longer silently looks supported. An unknown name **without** a URL
retains the existing request-time `ProviderError`. No aliases or generalized protocol registry are
added.

## Shared request, response, and cost flow

The shared engine sends one non-streaming `POST <base>/chat/completions` request with the native
`model`, the case messages, and supported `parameters`. `parameters.model`, `parameters.messages`,
and `parameters.stream` are **reserved** and rejected as configuration errors before HTTP, so a
parameter cannot replace the declared model or benchmark case, or switch a non-streaming parser to a
streaming response. This hardening also applies to branded adapters using the shared transport.
OpenAI-compatible targets vary; unsupported parameters receive the target's ordinary HTTP error and
no universal parameter compatibility is promised.

The adapter extracts the first choice's string message content, optional non-negative token counts,
the returned model when present, and latency. Cost stays provider-reported when an adapter already
supplies it, otherwise configured token pricing when complete, otherwise `None`. The generic adapter
supplies no provider-reported monetary cost, so a custom observation is either `configured_pricing`
or **unknown cost**; unknown is not zero, and aggregated cost remains unknown when observations lack
cost. The common error normalizer maps auth, rate, server, response, timeout, and network failures
without embedding response bodies, request headers, or exception text.

## Packaging, verification, and limitations

Serialized `schema_version: "0.1"` is unchanged. Existing provider integrations, credentials,
validators, artifact formats, CLI `validate`/`benchmark` behavior, Python API, and benchmark engine
remain compatible with 0.2.1. There is no new CLI command: `inferencefit validate` checks the
contract and `inferencefit benchmark` calls the same public engine. The packaged Agent Skill and its
references are updated minimally and still prefer a branded adapter, using `custom` only for a
supplied or documented endpoint.

Release verification is **offline**: full pytest, Ruff lint and format, wheel and sdist build,
Twine, distribution audit, clean installations, installed CLI and generic offline smoke, preset and
Skill smoke, secret scan, and diff check. No external paid key or live internet request is required;
a deterministic local HTTP server may augment mocked HTTP tests.

This release supports standard optional Bearer auth only; custom request **headers** are deferred,
because a plain `headers:` mapping would be serialized into artifacts and invite secret leakage.
Gateways that require other headers remain a documented limitation. Also out of scope: other
protocol families, Anthropic-compatible generic APIs, plugin or entry-point loading, model catalogs,
web discovery, automatic rankings, pricing or key discovery, new presets, Cloud/auth/billing, and
arbitrary code execution. Local arbitrary endpoints can reach localhost and private networks by
design; the user remains responsible for trusting an endpoint before sending benchmark prompts.
