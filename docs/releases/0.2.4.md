# InferenceFit 0.2.4 — native Anthropic (Claude)

InferenceFit 0.2.4 adds native, non-streaming Anthropic Messages benchmarking while retaining
serialized `schema_version: "0.1"` and the existing CLI, Python API, and daemon workflow.

Use `provider: anthropic` with an explicit current model ID; `provider: claude` is an alias for
the same adapter. Model names never infer providers. Set `ANTHROPIC_API_KEY` or an opaque
`credential_ref`, which takes precedence. No Anthropic SDK dependency, model registry, or
streaming path was added.

The adapter sends leading system prompts as top-level `system`, preserves user/assistant messages,
and extracts text blocks and usage from Messages responses. It rejects unsupported message shapes
and reserved `model`, `messages`, `system`, and `stream` parameters before HTTP. A default
`max_tokens` of 1024 applies when no output bound is configured. The `max_output_tokens` alias is
accepted, and temperature is sent only when explicitly configured.

Reported cache creation and read tokens contribute to input token totals. Cost is unknown unless
complete usage and explicit `pricing` permit an estimate. Static prices do not account for
cache-specific rates. Resolved secret values never appear in specs, manifests, observations,
results, logs, errors, examples, or artifacts; the existing opaque `credential_ref` persistence
contract remains unchanged.

An explicit `base_url` on a named candidate keeps the established generic chat-completions
override. For native Anthropic Messages, omit it. Unknown-provider plus `base_url` remains a
deprecated compatibility route; new generic endpoints use `provider: custom`.

See [the Anthropic example](../../examples/anthropic/README.md) for a bounded live smoke
configuration. Ordinary CI uses mocked HTTP and does not spend provider credits.
