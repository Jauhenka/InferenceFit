# InferenceFit 0.1.0

InferenceFit is a local-first tool for evaluating LLM configurations against your workload and
deterministically choosing among the configurations that satisfy your constraints. This first
public release includes file-based evaluation specs and datasets, declarative validators,
quality/cost/latency/reliability metrics, Pareto analysis, a runtime-valid two-stage fallback
cascade, resumable filesystem artifacts, a CLI, an async Python API, and a local daemon.

## Install

InferenceFit requires Python 3.11 or newer.

```bash
pip install inferencefit
```

## Smallest offline example

From this release's source checkout, the bundled fixture example is deterministic and requires
no API key or network access:

```bash
inferencefit validate examples/basic/eval.yaml
inferencefit benchmark examples/basic/eval.yaml
```

The run writes its result bundle and `routing-policy.yaml` under
`.inferencefit/runs/<run-id>/`.

The same evaluation is available through Python:

```python
import asyncio

from inferencefit import benchmark

result = asyncio.run(benchmark("examples/basic/eval.yaml"))
print(result.recommendation)
```

## Provider scope

The `fixture` provider is the offline, deterministic default for examples and CI. Real providers
use a general non-streaming OpenAI-compatible chat-completions adapter. Fireworks and DeepSeek
were exercised end to end against their real APIs during the E0.5 validation pass; presets also
exist for OpenRouter, Ollama, and vLLM, or an evaluation can supply another compatible endpoint.
Provider prices are explicit snapshots in the evaluation spec rather than live or invoice data.

## Current limitations

This is a pre-1.0 release: serialized contracts and public APIs may change before 1.0. The adapter
supports non-streaming chat completions only, routing is limited to a simple two-stage cascade,
and the HTTP daemon defaults to loopback but has no authentication and must not be exposed to an
untrusted network. InferenceFit does not include a hosted Cloud/SaaS service, accounts,
distributed workers, a traffic proxy, browser UI, learned routing, training, or non-Python SDKs.
