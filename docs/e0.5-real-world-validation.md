# E0.5 real-world validation

Validation was performed on 2026-09-21 local time (2026-09-20 UTC). This report distinguishes provider transport success, runtime JSON-schema validity, and exact task correctness.

## Workloads and sanitization

The requested root files matching `extract_lead_semantic_units_testcases*` and `merge_new_offers` were searched for in the working tree, ignored files, and complete Git history. No matches were present. Their input structures, expected outputs, validation logic, and failure cases therefore could not be inspected. A merge-offers example was not created because the unavailable source made it impossible to establish that it was distinct rather than redundant.

The committed example is synthetic and derived only from the behavioral requirements in the E0.5 brief:

- `examples/lead_semantic_units/dataset.jsonl`: 24 English cases covering common extraction, multiple ordered units, optional/missing facts, fragments, ambiguity, corrections, duplicate facts, exclusions, signatures, and current-state noise.
- `dataset.smoke.jsonl`: four cases spanning easy, multi-unit, incomplete, and corrected input.
- `dataset.multilingual.jsonl`: eight cases, two each in Russian, Ukrainian, Belarusian, and Polish.
- `fixtures/cheap.jsonl` and `fixtures/strong.jsonl`: illustrative—not historical or live—responses used to demonstrate deterministic optimization and schema-gated fallback.

All names, contacts, organizations, products, requirements, dates, and identifiers are invented. The output contract is `{"units":[{"type": ..., "value": ...}]}`. JSON Schema is the only runtime routing gate; whole-array exact comparison is evaluation-only.

## Integration findings

### DeepSeek preset was missing

- Symptom: a `provider: deepseek` candidate required an explicit `base_url`, and `credential_ref: deepseek-main` did not fall back to `DEEPSEEK_API_KEY`.
- Root cause: DeepSeek was absent from the endpoint and credential fallback maps.
- Fix: add only the `https://api.deepseek.com` preset and `DEEPSEEK_API_KEY` fallback; continue using the generic adapter.
- Regression tests: `test_deepseek_preset_uses_documented_chat_endpoint` and `test_deepseek_credential_falls_back_to_provider_environment_variable` failed before the map entries and pass afterward without network calls.

### Default reasoning exhausted the first smoke budgets

- Fireworks diagnostic run `20260920T225919Z-e312a0` returned a reasoning trace in `content` for all four cases and used all 1200 allowed output tokens; all schema checks failed.
- Fireworks diagnostic run `20260920T230239Z-cd0c7e` added JSON Schema response mode but still returned reasoning in `content` and used all 1200 output tokens, demonstrating that this model also needed the explicit reasoning-off parameter.
- DeepSeek diagnostic run `20260920T225937Z-0cdf3e` returned empty `content` for all four cases after using all 1200 output tokens. The behavior matches DeepSeek's documented default-enabled thinking mode and JSON-output warning.
- Root cause: the provider models defaulted to reasoning, while the extraction specs capped completion at 300 tokens and needed only the final JSON.
- Fix: set DeepSeek `thinking.type: disabled`; set Fireworks `reasoning_effort: none` and supply the full JSON Schema response format. The adapter already passed these parameters correctly, so no provider abstraction change was justified.
- Verification: the corrected smoke and full runs produced schema-valid JSON for every case with sharply lower output-token use.

No Markdown-fenced JSON, malformed final JSON, provider error, retry, or missing usage field occurred in the final runs. Empty content in the diagnostic DeepSeek run became validator-failure observations rather than a crash, keeping provider transport status distinct from task failure.

## Limitations

- The requested production-derived files were unavailable, so format fidelity and the distinctness of `merge_new_offers` remain unvalidated.
- Multilingual cases were validated with fixtures only, not paid providers.
- Live error branches (429, timeout, 5xx, cancellation) were not naturally triggered; they remain covered by offline tests rather than this live pass.
- The adapter does not persist provider `finish_reason`, reasoning content, cache-hit token detail, or provider-rated invoice cost. E0 metrics use normalized content and aggregate token fields only.
- DeepSeek peak/off-peak and cache-hit pricing cannot be represented simultaneously by one static two-rate pricing snapshot.
- Exact-span validation is intentionally strict and reveals annotation/model disagreements; it is not a semantic-equivalence score.

## Release-readiness conclusion

E0's architecture was exercised end to end against both real APIs: requests, normalized responses, validation, usage, static cost calculation, latency, observations, optimization, Pareto selection, routing policy, artifacts, and resume all completed. Before `0.1.0` / TestPyPI, the missing source-file fidelity review should be resolved if those private workloads are still a release criterion; package publication itself was intentionally not attempted.
